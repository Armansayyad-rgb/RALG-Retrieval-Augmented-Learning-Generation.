# Data Rights Inventory

This inventory records the repository's current engineering classification of datasets, evaluation corpora, runtime uploads, tokenizers, and model assets. It is not legal advice. Where provenance or license scope is uncertain, the conservative release classification controls.

## Classification rules

- **PROJECT-OWNED / PROVENANCE ESTABLISHED** — project-authored material with a documented creation chain.
- **THIRD-PARTY / NOTICE REQUIRED** — upstream material whose redistribution terms and attribution must be preserved.
- **PROVENANCE INCOMPLETE** — source, license, or derivation chain is not sufficiently documented.
- **EXCLUDE FROM COMMERCIAL DISTRIBUTION** — do not place in a commercial release package until the identified provenance/license issue is resolved.

## 1. Training and knowledge data

### `data/wikitext_v2.txt`

- Source: Salesforce WikiText material obtained through the `salesforce/wikitext` distribution path used by the project.
- Purpose: training/development and configured knowledge data.
- In Git: yes.
- License status: Creative Commons Attribution-ShareAlike; repository evidence currently contains a version ambiguity between CC BY-SA 3.0 metadata and CC BY-SA 4.0 documentation.
- Release classification: **THIRD-PARTY / NOTICE REQUIRED — LICENSE VERSION TO VERIFY**.
- Commercial-distribution rule: preserve attribution/share-alike obligations and verify the authoritative upstream license version before commercial redistribution.

### `data/train.txt`

- Source: incomplete repository provenance; content appears Wikipedia-derived.
- Introduced: initial repository history and not generated by the current WikiText downloader.
- Purpose: historical training/development paths (`src/train.py`, `src/train_tokenizer.py`, `src/build_knowledge.py`).
- In Git: yes.
- Production runtime required: no.
- License/provenance: not sufficiently established.
- Checkpoint lineage: no reliable immutable record proves which model/tokenizer artifacts, if any, were trained from this file.
- Risk: high.
- Release classification: **PROVENANCE INCOMPLETE — EXCLUDE FROM COMMERCIAL DISTRIBUTION**.

## 2. Evaluation corpora

### Stage 5 RFC corpus

- Source: IETF/RFC Editor.
- In Git: yes, under `evaluation/stage5_documents/` with provenance manifest `evaluation/stage5_source_manifest.jsonl`.
- Rights: governed by IETF Trust legal provisions; preserve required notices/attribution.
- Release classification: **THIRD-PARTY / NOTICE REQUIRED**.

The Stage 5 benchmark questions/results are project-generated evaluation infrastructure. Independently sourced RFC documents do not make the benchmark authoring independent.

### Holdout V1

Python Enhancement Proposal material is used as upstream technical source content. Preserve source attribution and the frozen evaluation record. Holdout V1 is historical/diagnostic evidence and must not be rerun or rewritten as fresh evidence.

### Holdout V2

The source notes were authored validation material derived from public technical documentation. They are not third-party-authored validation evidence. The blind result remains immutable and separate from data-rights classification.

### Holdout V3

Seven authoritative upstream technical sources are committed with source manifests/revisions and file-level attribution described in `THIRD_PARTY_NOTICES.md`. Each upstream license controls its respective source artifact. Holdout V3 remains frozen historical evidence and must not be modified to improve presentation or results.

## 3. Runtime uploads

- Source: user/customer-provided at runtime.
- Repository path: runtime persistence directories are ignored and are not release inputs.
- Ownership/license: supplied content remains subject to the uploader's rights and agreements; it is not automatically relicensed by the RALG repository license.
- Release classification: **REFERENCE-ONLY / NOT REDISTRIBUTED** unless separately authorized.

## 4. Tokenizers and generated artifacts

### `data/tokenizer_v2.json`

- In Git: yes; active tokenizer artifact.
- Claimed lineage: trained/generated from project training data associated with WikiText workflows.
- Distribution note: because the precise upstream license version for WikiText remains unresolved in repository evidence, do not overstate the tokenizer's independent commercial-clearance status.
- Release classification: **PROJECT-GENERATED / UPSTREAM-DATA LICENSE REVIEW REQUIRED**.

### `data/tokenizer.json`

Legacy tokenizer artifact. It is not the primary active tokenizer. Treat it as legacy until a release-manifest review confirms a reason to distribute it.

## 5. Model/checkpoint binaries

No custom checkpoint binaries are committed to Git. Local names observed/documented include:

- `checkpoints/v2/reasoning_model_v1.pt`;
- `checkpoints/v2/instruction_model_v4.pt`;
- `checkpoints/embedding_model.pt`;
- other historical SmallLM checkpoint names.

Repository authorship of training code is not, by itself, sufficient evidence of a checkpoint's training-data lineage. The reviewed repository does not contain immutable training logs, exact dataset pins/hashes, complete build records, and checkpoint-generation records sufficient to establish a clean commercial provenance chain for all custom checkpoints.

Current release classification for custom checkpoints: **PROVENANCE INCOMPLETE — EXCLUDE FROM COMMERCIAL DISTRIBUTION until the chain is reconstructed and verified**.

Optional Qwen model files are third-party assets, not project-owned checkpoints. Their Apache 2.0 terms and notices apply independently; see `THIRD_PARTY_NOTICES.md`.
